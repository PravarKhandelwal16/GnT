# Give & Take

A community marketplace for unused things. Members list items, earn credits, and spend them on what others no longer need. Exchanges happen in person and are confirmed with a QR code. Staff run the marketplace from a separate workspace.

**Stack:** React 18, TypeScript, Vite and Tailwind · Java 21, Spring Boot 3.3, Spring Security and JWT · MySQL 8 and Flyway · ImageKit (optional)

## Run it locally

### Without MySQL

Uses a local H2 database file that starts empty and survives restarts.

```powershell
# Terminal 1
cd backend
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=h2"

# Terminal 2
cd frontend
npm install
npm run dev
```

Open http://localhost:5173. The market starts with 8 sample products from two sample sellers; sign up to try it. To make your account an owner, put your email in `backend/.env` as `OWNER_EMAILS=you@example.com` **before** signing up (or restart the backend after).

- Data is stored in `backend/data/`. Delete that folder to start over.
- Browse the tables at `http://localhost:<backend port>/h2-console` with JDBC URL `jdbc:h2:file:./data/gnt-local`, user `sa` and an empty password.

### With MySQL

```powershell
docker compose up -d                 # MySQL 8 on port 3306
cd backend
copy .env.example .env               # then fill it in (see below)
.\mvnw.cmd spring-boot:run
```

### Tests

```powershell
cd backend
.\mvnw.cmd test
```

## Configuration

The backend reads environment variables, or `backend/.env` in development. The frontend reads `VITE_API_URL` when it is **built**.

| Variable | Required | Purpose |
|---|---|---|
| `JWT_SECRET` | Yes | Signs login tokens. At least 32 random characters (`openssl rand -base64 48`). The app won't start without it. |
| `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | Yes | MySQL connection. |
| `OWNER_EMAILS` | First deploy | Comma-separated emails that become owners when they sign up. |
| `FRONTEND_URL` | Yes | Public site address, used in password-reset links. |
| `CORS_ALLOWED_ORIGINS` | Yes | The site address(es) allowed to call the API. |
| `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM` | Recommended | SMTP for password-reset email. Without it, reset links only appear in the server log. |
| `IMAGEKIT_PUBLIC_KEY`, `IMAGEKIT_PRIVATE_KEY`, `IMAGEKIT_URL_ENDPOINT` | Recommended | Image hosting. Without them, uploads are saved to the server's disk (`MEDIA_LOCAL_DIR`). |
| `MEDIA_PUBLIC_BASE_URL` | If not using ImageKit | Public backend address used in image links. |
| `SERVER_PORT` | No | Defaults to 8080. |
| `EXCHANGE_RESERVATION_HOURS` | No | Time to meet after a reservation. Defaults to 48. |
| `LISTING_MAX_CREDIT_VALUE`, `LISTING_MAX_ACTIVE_PER_USER` | No | Default 5,000 and 25. |
| `API_DOCS_ENABLED` | No | `true` serves Swagger UI at `/swagger-ui.html`. Off by default. |
| `VITE_API_URL` | Yes (frontend build) | Public backend address, for example `https://api.example.com`. |

## Deploy on Render

The repository includes a Render Blueprint (`render.yaml`) that creates two services, with no Docker:

| Service | What it is |
|---|---|
| `giveandtake-api` | The Spring Boot backend. Render has no Java runtime, so it uses Render's Node environment, and `backend/render-build.sh` downloads JDK 21 and Maven during the build. |
| `giveandtake-web` | The React site, as a static site. |

Render's databases are PostgreSQL only, so MySQL comes from **Aiven** (free tier).

### 1. Create the database on Aiven

1. Sign up at [aiven.io](https://aiven.io) and create a **MySQL** service on the free plan.
2. When it's running, open it and copy the **Host**, **Port**, **User** and **Password**. The database is called `defaultdb`.
3. Your `DB_URL` is:
   ```
   jdbc:mysql://HOST:PORT/defaultdb?sslMode=REQUIRED&serverTimezone=UTC
   ```
   The tables are created automatically the first time the backend starts.

### 2. Create the services on Render

1. In Render, choose **New → Blueprint** and connect this GitHub repository (branch `main`).
2. Render asks for the values marked as secret:
   - `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`: from Aiven.
   - `OWNER_EMAILS`: the email you'll sign up with, so you become the owner.
   - `IMAGEKIT_PUBLIC_KEY`, `IMAGEKIT_PRIVATE_KEY`, `IMAGEKIT_URL_ENDPOINT`: **new** keys from ImageKit. They are required, because Render wipes its disk on every deploy and uploads would vanish without them.
   - `MAIL_*`: optional SMTP for password-reset email. Leave them blank to skip.
   - `SAMPLE_SELLER_PASSWORD`: optional. Set it if you want to log in as the sample sellers (`asha@samples.giveandtake.invalid`, `rohan@samples.giveandtake.invalid`), for example to hand over a sample item someone reserved.

   `JWT_SECRET` is generated by Render. The public addresses (`VITE_API_URL`, `FRONTEND_URL`, `CORS_ALLOWED_ORIGINS`) are written out in `render.yaml`, because Render's automatic `fromService` value is the internal name, which browsers can't reach. If Render gives your services different addresses, update those three lines.
3. Click **Apply**. The first backend build takes a few minutes because it downloads Java.

### 3. Open the site

1. Open the `giveandtake-web` address, for example `https://giveandtake-web.onrender.com`.
2. Sign up with your `OWNER_EMAILS` address, then go to **Account menu → Owner workspace**.
3. The 8 starter products from the sample sellers Asha Rao and Rohan Mehta are already on the market. They are listed automatically when the backend starts and never duplicated. To leave them out, set `SAMPLE_DATA=false`; to log in as those sellers, set `SAMPLE_SELLER_PASSWORD`.

### Things to know about Render's free plan

- The backend sleeps after 15 minutes without visitors, so the first page after a quiet spell takes about a minute to load. Paid plans stay awake.
- Reservations that expire while it sleeps are settled as soon as it wakes.
- Pushing to `main` redeploys both services automatically.

### Deploying somewhere else

Build with `.\mvnw.cmd clean package` (always include `clean` so deleted files can't linger in the build), then run `backend/target/backend-0.0.1-SNAPSHOT.jar` with Java 21 or newer and the variables above. Build the site with `npm ci` and then `npm run build` with `VITE_API_URL` set, host `frontend/dist`, and send every unknown path to `index.html`.

### Before going live

- [ ] Replace the ImageKit keys and JWT secret that were once committed to this repository; they are still in its git history.
- [ ] Set every required variable above. Use a new `JWT_SECRET`, not one from development.
- [ ] Configure SMTP so members can reset their own passwords.
- [ ] Use ImageKit for uploads. On Render this is required; elsewhere, without it, put `MEDIA_LOCAL_DIR` on persistent storage.
- [ ] Serve both the site and the API over HTTPS. Phone browsers only allow the QR scanner camera on HTTPS pages.
- [ ] Have the Terms and Privacy pages reviewed.

### Known gaps

- No rate limiting on login or password reset. Add it at the proxy or in the app.
- Changing your password doesn't sign out your other devices.
- New listings go live straight away; there is no approval step.
- The Gemini chatbot and AI moderation described in older documents are not built.

## How credits work

| Event | Effect |
|---|---|
| Sign up | +350 |
| List an item | Seller +40% of its value |
| Reserve an item | Buyer −100%, held until the exchange ends |
| Exchange completes | Seller receives the rest, so their total equals the item's value |
| Cancelled, or expired with no confirmation | Buyer refunded, item relisted |
| Listing removed by its owner | Listing reward taken back |

Every balance change goes through `CreditLedger`, which updates the balance and writes a `credit_history` row in the same database transaction. See [docs/DATA_MODEL.md](docs/DATA_MODEL.md).

## How an exchange works

1. The buyer reserves an item. Credits are held and the pickup address and phone numbers are shared.
2. They have 48 hours to meet.
3. Only the buyer can see the handover code. The seller scans it, or types it, in person.
4. The buyer confirms receipt, which completes the exchange.
5. If time runs out after either person confirmed, the exchange completes. If nobody confirmed, the buyer is refunded.

## Staff access

Staff use the workspace at `/admin`. Every action requires a reason and is written to an audit log that can't be edited.

| | Team (moderator) | Owner (admin) |
|---|---|---|
| Overview numbers | ✓ | ✓ |
| Work the report queue | ✓ | ✓ |
| Remove or restore listings | ✓ | ✓ |
| Look up members, ledgers and exchanges | ✓ | ✓ |
| Suspend or reactivate members | Members only | ✓ |
| Adjust credit balances | | ✓ |
| Cancel an exchange and refund the buyer | | ✓ |
| Change roles | | ✓ |
| Read the audit log | | ✓ |

The server enforces these rules; the app only hides what a role can't use.
